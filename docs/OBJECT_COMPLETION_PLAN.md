# Завершение блока «Объект»

Объём: существующие вкладки карточки объекта и кабинет сотрудника, без новых
модулей, изменения production-данных, миграций и production promotion.

Критерии приёмки:
- Все 13 вкладок и вложенные виды сохраняют общий стиль, права, русские подписи
  и управляемую прокрутку на 1440/390px в светлой и тёмной теме.
- Формы документов, контактов и инцидентов имеют понятные ошибки, отмену,
  управление фокусом и защиту от повторного сохранения там, где она нужна.
- План показывает записанную потребность, дефицит, избыток и неизвестные значения;
  резерв не считается назначенным выходом, факт не перезаписывается планированием.
- Изменение плана после ответа сотрудника не считается подтверждением новой смены.
- Время смены соответствует часовому поясу объекта, включая ночной переход даты.
- Отметки и часы сотрудника видны менеджеру и в табеле; ручной факт и согласованный
  период защищены. Невыход требует причину, будущие часы не принимаются.
- Выдача, блокировка, разблокировка, перевыпуск и отзыв ссылки работают;
  завершённое увольнение отзывает доступ, плановое увольнение не закрывает его раньше.
- Права/tenant scope проверяются сервером; UI не считается доказательством доступа.

Порядок: аудит → исправление найденных нарушений → SQL/RLS проверки на временной
базе → настоящий HTTP/session/driver сценарий на временной базе → unit/lint/build
→ браузерные вкладки и формы → публикация Preview → итоговый отчёт.

PGlite-прогон дополняется отдельной приёмкой на native PostgreSQL. Рабочая база
заказчика в испытаниях не участвует; production promotion — отдельный выпуск.

## Итоговая приёмка — 13.10.2026

Этапы аудита, исправлений и локальной проверки завершены. Выявленные нарушения
устранены: время новой смены, дата завершения увольнения, потеря связи ответа с
назначением, устаревшее подтверждение после изменения плана, учёт отказа в покрытии,
локальный следующий день менеджера, сдвиг календарной даты документа при hydration.

модулей на этом socket не был принят как доказательство native PostgreSQL: стенд
ограничен одним PostgreSQL engine/portal. Рабочая база, конкурентные соединения,
реальные выплаты и реальные сотруднические ссылки не изменялись и не проверялись
разрушающими действиями. Проверенная поставка — Preview, не production promotion.

## Дополнительная приёмка на native PostgreSQL — 13.10.2026

В отдельной временной VM поднята PostgreSQL 18.6. Приложение запускается из
production build, подключается через postgres.js, использует настоящий парольный
вход и Secure session cookie. База содержит только миграции и фикстуры проекта.

Найдены и исправлены три нарушения, которые прежний стенд не выявлял:
- запрос табеля сортировал DISTINCT-выборку по отсутствующему в ней выражению;
- аналитика использовала `day` как неявный SQL-псевдоним;
- изменение плана и запись часов брали строки в разном порядке и могли привести
  к deadlock. Планирование теперь сначала блокирует сотрудников по UUID, как
  ответы сотрудника, управление ссылками и увольнение, затем читает назначения
  и блокирует строки табеля. Это действует и для массового плана/генерации.

Native-проверка не принимает оболочку страницы за успех: в конце проверяет
серверный журнал на ошибки загрузки модулей и SQL.

| Сценарий | Результат |
|---|---|
| Все 13 вкладок с настоящим входом, 1440/390px, light/dark | 52 сочетания без горизонтального переполнения и скрытого SQL fallback |
| План изменён первым, сотрудник одновременно отправляет старые часы | Новый план сохранён; устаревшие часы отклонены без deadlock |
| Часы отправлены первыми, менеджер одновременно меняет план | Факт сохранён; переписывание факта планом отклонено |
| Блокировка ссылки и уже ожидающий запрос сотрудника | После завершённой блокировки запрос отклонён с 403 |
| Перезагрузка кабинета и новый вход менеджера | Записанные часы сохранены и доступны менеджеру |
| Согласование, блокировка/разблокировка, перевыпуск, увольнение | Часы защищены; старый токен закрыт; увольнение отзывает чтение и запись |

Воспроизведение: создать **пустую** локальную базу `operis_acceptance` на
127.0.0.1:55439, доступную тестовой роли `ubuntu`, выполнить `npm run build`, затем
`npm run test:employee-native`. Тест не читает внешний DATABASE_URL, проверяет
пустоту базы до миграций и использует фиксированный локальный адрес. На Ubuntu
26.04 для Playwright 1.55 при испытании использовался
`PLAYWRIGHT_HOST_PLATFORM_OVERRIDE=ubuntu24.04-x64`.

Ограничения: native-стенд запускает приложение под владельцем временной базы;
отдельный SQL/RLS прогон проверяет роль NOSUPERUSER/NOBYPASSRLS. Платёжные сценарии,
рабочие данные и реальные ссылки сотрудников не изменялись. Lint изменённых
файлов: 0 ошибок; в `lib/data/service.ts` есть прежнее предупреждение о неиспользуемом
`index` в demo списка задач запуска, не относящееся к этим изменениям.
