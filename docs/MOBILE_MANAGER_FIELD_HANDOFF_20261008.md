# OPERIS — мобильное рабочее место менеджера /field

**Дата:** 08.10.2026. **Статус:** реализация в отдельной ветке; полный CI пройден; миграция staging/prod НЕ применена, публикации рабочего маршрута в main НЕТ.

## Назначение и UX
Согласован пользовательский сценарий: менеджер на объекте должен быстро проверить фактическую явку, позвонить отсутствующему, встретить новичка, проверить этапы первого дня, сохранить условия первой встречи на новом объекте и согласовать запросы сотрудников. С компьютера остаются подробные планирование, расчёты и табели. Не строить новую CRM и не дублировать сущности.

Ветка `feature/mobile-manager-field-20261008` **основана на** `feature/worker-confirmations-20261008` (согласованный кабинет сотрудника). До перехода в main требуется интегрировать зависимый PR личного кабинета сотрудника, а не переносить ветку в main напрямую.

## Реализовано
- `/field` — новый экран «Рабочий день менеджера» внутри существующего `AppShell`, с мобильной навигацией «Сегодня / Первый день / Решения / Выезды / Ещё», плотной светлой и тёмной темой, без ломания десктопных таблиц.
- `app/mobile-manager.css` — локальные мобильные правила, сохранение левого меню на компьютере.
- `components/MobileManagerWorkspace.tsx` — свод по объектам и дневной/ночной смене, поиск, список явки, звонок, индивидуальная/массовая отметка присутствия с явным подтверждением, причина неявки, возврат на проверку.
- `lib/operations/mobile-manager.ts` — чтение через существующие `listObjects/listWorkers/listShifts`, события явки пишутся **только** в уже существующую `attendance_events`. Нет параллельного табеля; нажатие «На месте» не записывает 11 часов. Сохраняются actor, timestamp, source; scope и capability проверяются на сервере.
- Новый сотрудник определяется по дате назначения на объект в `worker_object_assignments`. Карточка первого выхода: встречен / пропуск и допуск проверены / документы / инструктаж / СИЗ / приступил к работе. Этапы сохраняются в `worker_first_day_checkpoints`, аудируются, используют ID сотрудника/объекта; «приступил» требует фактической явки. Чек-лист **не заменяет официальный допуск СБ**.
- `/api/field-manager` — авторизованные GET/POST, запрет сохранения для demo, серверная проверка ролей и принадлежности к объекту, проверка существующего назначения на смену, массовое действие ограничено 50 людьми.
- Мобильная анкета «Выезды» использует `launch_site_visits` и операционные факты; расширен существующий `/api/launches/[id]/visits/[visitId]` поддержкой `itemUpdate`: обновляет один вопрос внутри транзакции, не заменяет остальные ответы целиком.
- Очередь «Решения» повторно использует действующий `/api/operations/worker-confirmations` для запросов на изменение смены, графика и рабочего времени.
- Существующий manifest навигации расширен ссылкой на `/field` в «Главная / Рабочее пространство», без создания нового первого уровня меню.

## Известные ограничения первой реализации
- Контроль «Первый день» работает по первой дате текущего назначения сотрудника на объект; кандидаты, ещё не переведённые в сотрудников, остаются в прежнем рекрутинговом/онбординг-контуре.
- На телефоне предусмотрено оперативное согласование изменения графика; глубокая помесячная сверка часов остаётся в существующем `/timesheets`.
- Оффлайн-синхронизация, push и автоматическое протоколирование телефонных разговоров в этой итерации не реализованы.
- Статический HTML-превью, если передан пользователю, содержит только вымышленные данные и не сохраняет ничего на сервер OPERIS.
