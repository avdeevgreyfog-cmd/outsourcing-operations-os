## Native PostgreSQL и E2E

Полный приёмочный прогон выполняется на отдельной копии с собственным endpoint:

- настоящий Next.js, postgres.js, HTTPS + Secure session cookie, парольный вход;
- план → условия → потребность на дефицит → кандидат → подтверждённый первый выход
  → ровно один сотрудник/назначение → наследование условий → график → часы → табель;
- индивидуальное исключение сотрудника без изменения условий объекта;
- неизвестная дата назначения остаётся SQL NULL; текущий план/табель доступны;
- двое конкурирующих запросов создания одной строки/версии/назначения;
- изменение условий и запись часов в обоих порядках;
- фиксация табеля и запись часов в обоих порядках: снимок согласован с итоговым фактом;
- повторный импорт/запрос не удваивает сущности или часы;
- фактическое отображение плана/дефицита/часов во всех связанных разделах;
- другой tenant не читает и не изменяет эти записи.

Синтетические фактические часы допускаются только в изолированной копии. Live-проверка
без таких часов подтверждает доступность операций и существующие данные, но не
доказывает новую рабочую запись часов.

они не считаются конкурентным прогоном. Отдельная гонка строк плана не доказана,
как и гонки условий с часами либо фиксации табеля с часами. Результат гонки условий
на эти сценарии не распространяется.
