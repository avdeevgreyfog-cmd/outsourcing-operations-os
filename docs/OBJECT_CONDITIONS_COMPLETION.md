# Условия специальности на объекте — 19.10.2026

## Пользовательский сценарий

Объект → Комплектация → Добавить специальность в план теперь сразу показывает
ставку, единицу оплаты, график, начало/окончание смены, длительность присутствия
и оплачиваемые часы, отдельный период и комментарий условий. Неизвестные значения
не заменяются сегодняшней датой или нулём. Строка численности и заполненные начальные
условия сохраняются одной транзакцией. Ошибка условий откатывает строку плана.

Это две связанные сущности: staffing_plan_targets хранит численность;
object_specialty_conditions — объект + специальность + смена + период. Условия
не записываются глобально в специальность и не ограничиваются текстом потребности.
Если активные условия уже есть, повторная запись при создании плана не создаётся.
Изменение численности не меняет оплату. Для изменения условий используется отдельная
новая версия с датой. Неуказанные поля видны в строке; история версий сохранена.

При прямом создании сотрудника доступна смена назначения: день/ночь/смешанная.
Назначение и карточка используют действующие условия, индивидуальная ставка имеет
приоритет. Прогноз планирования и кабинет сотрудника разрешают версию графика на
каждую дату. Массовая серия учитывает датированные индивидуальные циклы, пропускает
выходные/несовпадающую смену с предупреждением. Уже сохранённый факт при этом не меняется.

Миграция 0078_worker_schedule_anchor.sql добавляет nullable anchor_date в историю
индивидуальных графиков: начало цикла отдельно от даты действия. Старые NULL имеют
прежний fallback; backfill, seed, очистка и пересчёт не выполняются.
