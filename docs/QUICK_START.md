# Быстрый старт действующего контура

Блок от 13.10.2026. Основа: `091c9fce999b251f07578dba12533990264bc6de` (личный пилот и завершённый блок объекта). Создание действующего объекта не требует заявки, КП, договора или задачи запуска.

## Объект

В реестре «Объекты» → «Добавить объект» для действующего объекта достаточно названия. Клиент, наше юрлицо, регион, адрес, менеджер и фактическая дата начала допускают отсутствие. Неизвестная дата сохраняется как NULL; сегодняшняя дата не подставляется.

Клиента, своё юрлицо и регион можно создать внутри формы. Перед записью выполняется проверка совпадений названия в доступной организации; совпадение предлагается выбрать. Ввод объекта сохраняется при вложенном создании. Действия используют существующие capabilities: `sales.client.create`, `organization.manage`, `admin.permissions.manage`; права не расширяются автоматически.

Карточка и реестр показывают незаполненный профиль. В настройках дополняются связи, адрес, даты и реквизиты выбранного клиента/юрлица. Изменение реквизитов проверяет версию и пишет историю. Незаполненный профиль не является выдуманным бизнес-статусом: объект остаётся `active`.

## Сотрудник

В реестре «Сотрудники» можно сохранить только ФИО. Пробелы не удовлетворяют минимуму, кнопка создания недоступна. Телефон, объект, специальность, ставка, оформление и дата необязательны; значения не заменяются датой сегодня или нулём.

Без полного назначения (объект, специальность, явно введённая дата) сохраняется статус `requires_assignment` — «Требует назначения». Предварительные сведения хранятся в `worker_profiles.onboarding_metadata`, отдельно от действующих назначений, оформления и ставок. Они сами не создают планы, часы или персональные ссылки. Первое подтверждённое назначение переводит сотрудника в `active`; ссылка становится доступна при наличии действующего назначения и нужных прав.

Из формы сотрудника доступно вложенное создание объекта и ввод новой специальности в существующий справочник. Неизвестный режим работы назначения допускает NULL. Дубли по нормализованному телефону не перезаписывают чужой профиль.

## Импорт

Кнопка «Импорт» в реестрах открывает общий мастер. XLSX-шаблон содержит листы «Объекты», «Сотрудники», «Назначения», «Часы». Ключи строк связывают листы; для существующих записей поддерживаются ID. Специальность назначения указывается названием из справочника (API также принимает ID).

Минимум объекта — название; сотрудника — ФИО. Назначение требует объект, сотрудника, специальность и достоверную дату начала. Историческим часам нужны дата, количество 0–24 и вид смены; пустые часы не означают 0. Листы назначений и часов можно пропустить.

Предварительная проверка не пишет данные. Показывает все строки, дубли, неоднозначные совпадения, конфликт статуса, пересечение назначений, отсутствие минимума, нарушение прав и попытки перезаписи фактов. Существующие профили автоматически не обновляются. Неоднозначный сотрудник не объединяется только по ФИО.

Запись атомарна и повторно сверяет digest предпросмотра с текущими данными и пользователем. Изменившиеся данные требуют новой проверки. Блокировки телефонов и сотрудников согласованы с прямым созданием и фиксацией табеля. Импорт не изменяет фиксированный период и не перезаписывает существующие часы; исторические часы используют существующий учёт времени и причину «Импорт исторического факта».

## Выпуск

Требуется миграция `0074_existing_contour_quick_start.sql`: nullable-связи объекта, metadata сотрудника, nullable work_mode и сохранение tenant integrity. Миграция не удаляет рабочие данные, не запускает seed и не выдаёт новые права. Применение схемы и выпуск кода должны быть согласованы. До этого новый код нельзя объявлять включённым в личном пилоте.

Main, beta и пользовательская база не изменялись во время разработки. Проверки используют отдельные fixture-базы; demo Preview не доказывает рабочую запись в организацию пользователя.

## Исправления блокеров действующего штата — 14.10.2026

`/organization/positions` падал из-за отсутствия подразделения в GROUP BY запроса штатных позиций. Рабочие специальности теперь явно показаны отдельно от должностных профилей организации; один компонент создаёт их на странице и внутри назначения, выбирая совпадение без дубля. Назначение использует общую боковую панель.

Миграция `0075_assignment_without_object_manager.sql` допускает явно неизвестного менеджера при действующем назначении; сохраняет tenant integrity, синхронизацию менеджера и закрытую историю. API изменения менеджера блокирует сотрудников по UUID до объекта, согласованно с назначением. Повтор того же назначения без изменений сохраняет строку и историю. Месячные часы карточки читаются из общего time_entries при наличии права просмотра часов.

Выбран вариант с обязательной достоверной датой назначения: без неё перенос создаёт профили, но не действующие назначения/исторические часы. Неизвестная дата запуска объекта допустима. Дата назначения не заменяется сегодняшней. Возможность активного назначения с неизвестной исторической датой в этом выпуске не заявляется.

`tests/existing-contour.browser.mjs` предназначен только для явно указанной изолированной копии sergey-work (отвергает live endpoint). Проверяет первые специальности, inline-создание, четыре исходных назначения, запись часов через UI, сохранение/табель/карточки, три объекта, две ширины и темы, повторную запись без дублей. Только после проверки исходных 3/4 записей создаёт отдельные временные fixtures в копии для гонки изменения менеджера и первого назначения в обеих очередностях. Тест меняет пароль fixture-владельца только в копии; никогда не использует пароль пользователя. Тестовые часы не переносятся в рабочий табель.

Приёмка этого исправления: 405 unit/route tests, build/TypeScript, targeted lint0 ошибок (прежний unused index), фактические запросы каталога в SQL/RLS suite. Full HTTP/browser E2E на копии завершён: 4 назначения, 4×10 тестовых часов, reload, табель и месячные часы карточки; исходные 3 объекта/4 сотрудника сохранены. Native manager/first-assignment race в двух очередностях прошёл. Рабочий табель тестовыми часами не заполняется.
