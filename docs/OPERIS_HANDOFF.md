Дата: 06.10.2026. База: beta `6956a32a2da9cac14e8f2295d2be360bca67d173`.

`main` / production этой итерацией не изменяются.

## Решения и изменения

Создание тендера приведено к тому же рабочему принципу, что создание заявки, без
механического копирования многошаговой формы заявки. Для текущего объёма тендерных
полей отдельный wizard создавал бы лишние переходы. Вместо этого один
`TenderCreateForm` используется и на `/tenders/new`, и в демонстрационном
`SalesDrawer`. Поля собраны в два смысловых блока: основные данные закупки и
условия/внутренняя привязка. Сохранены существующие API-поля, tenant-связи,
автоматическое назначение текущего пользователя и дальнейшая работа в полной
карточке. Демозапись остаётся только в памяти страницы и исчезает после reload.

Аналитика тендеров пересобрана по композиции заявок:
фильтры → пояснение методики → KPI → воронка и разрывы → динамика →
риск подачи / готовность документов → разрез эффективности / причины →
детализация этапов. Тендерные данные не сокращались: сохранены количество,
бюджет, численность, Bid / No Bid, подачи, победы, сроки, документы, причины
No Bid и проигрыша, площадки, заказчики и ответственные. Два отдельных блока
причин объединены в один переключаемый рабочий блок. Воронка использует
условный силуэт, как заявки; ширина этапа не выдаётся за точную количественную
шкалу. Неизвестные бюджет/численность по-прежнему показываются как «—».

Схема БД, миграции, write API, capability model и доменные переходы не менялись.

Реестр уже перенесён в beta предыдущим этапом; повторного редизайна нет.
Полная карточка сохраняет семь вкладок и все существующие процессы. Основной

явно доступна только для чтения. Даты ввода/отображения — МСК; исходные значения

На сервере ограничена загрузка экономики правом и scope сценария. Изменение
результата защищено capability независимо от этапа, обычный перенос с прежним
результатом сохраняется. Анализ объединяет новые условия с существующими ключами.

# OPERIS · Передача текущей итерации

Дата: 05.10.2026. При продолжении сверить этот checkpoint с GitHub, рабочим деревом и Vercel: ссылки и проверки ниже относятся к конкретной итерации, а не ко всему продукту.

## Цель и решения

Перенести `/tenders` на общий реестровый контракт заявок и сотрудников. Сохранены серверные карточки, расчёты, согласования, документы, импорт, связи и девять доменных этапов. Общие controls, 42/60 px, 20 доступных колонок с исходными восемью по умолчанию, два уровня группировки, виды без поиска, нижний бегунок, доска 228/210 px и просмотр 490 px. KPI находятся в аналитике. Виды сохраняют только предпочтения браузера с tenant/member/role/capability scope.

Аналитика различает текущий снимок, когорту создания и календарные события, включая старые тендеры. Только подтверждённые события; нет восстановления пропущенных этапов или синтетической demo-истории. Неизвестные знаменатели дают «—». Суммы — по заполненным текущим бюджетам и потребности, без исторических снимков. Старый trigger не хранит очистку результата: показывается последний записанный результат; ограничение раскрыто в интерфейсе. Миграций и изменений API записи нет.

Демо-записи создания/импорта живут только в памяти до reload и не включаются в аналитику. Демо-reаd scope наследуется от коммерческих заявок, одинаков для реестра, подробной карточки и аналитики. В рабочей системе доступ продолжает загружаться из БД. Общий `SalesDrawer` получил только необязательный overline с прежним значением по умолчанию.
