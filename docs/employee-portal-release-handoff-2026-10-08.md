## 1. Что уже согласовано

Пользователь посмотрел и одобрил v5 личного кабинета сотрудника в телефоне и на компьютере. Сохранять плотный русский B2B-стиль OPERIS, работающий продукт, текущие ID/маршруты/роль/историю, без параллельной CRM, без localStorage как источника истины.

Цель: **Объект → планирование смен → персональный кабинет сотрудника → ответ о выходе / фактические часы → менеджерская сверка → табель**.

Функциональность:
- Менеджер определяет модель графика на объекте: планирует менеджер или сотрудник. Сотрудник **не видит** техническую настройку полномочий.
- Менеджер выбирает конкретному сотруднику 5/2, 6/1, 2/2, 3/3 и др., фиксированные или плавающие выходные, день/ночь, дату начала нового графика. При фиксированном 5/2: суббота/воскресенье; при фиксированном 6/1: воскресенье.
- Рабочие смены и дни отдыха выводятся сотруднику автоматически, не надо ежедневно заполнять график.
- Сотрудник подтверждает предстоящий выход одним нажатием; при изменении планов сообщает причину; управляемые изменения фиксированного графика и рабочего времени направляются менеджеру на согласование.
- «Ближайшие дни»: простой список дат и смен; форма изменения открывается **под нажатой датой** на мобильном и desktop.
- При разрешённых плавающих выходных сотрудник может выбрать дни отдыха на полную неделю; для 5/2 — два, для 6/1 — один; соблюдаются границы горизонта планирования.
- После завершения смены сотрудник подтверждает фактические часы. Ночные часы привязаны к дате начала ночной смены, а не к календарной дате её окончания.
- Месячный табель с переключением назад/вперёд; **плановые** смены не засчитываются в фактические часы/смены. Состояния сотруднику: «Передано» и «Согласовано» (последнее — только после менеджерского подтверждения). Без технических пояснений и сырых enum.
- Документы: чек-лист по объекту и типу оформления; **без загрузки паспортов и сканов**. СИЗ: что выдано/не выдано, размер одежды/обуви. Управление видимостью «Документы» и «Спецодежда» по объекту — у менеджера, выключение не удаляет данные.
- Контакт ответственного менеджера.
- На мобильном три основных пункта: «Смены», «Табель», «Ещё». Без верхнего «Сценарий», статусных/внутренних служебных подписей.

## 3. Установленные блокеры выпуска (08.10.2026)

**Блокер A — production и staging PostgreSQL не верифицированы.**
- Workflow `Staging Database` остановлен на `PRODUCTION_DATABASE_URL is not configured in the production environment`, пример: https://github.com/avdeevgreyfog-cmd/outsourcing-operations-os/actions/runs/37676938868 .
- Workflow `Release Readiness` также не может подтвердить разные базы: https://github.com/avdeevgreyfog-cmd/outsourcing-operations-os/actions/runs/37741346646 .
- **Нельзя** заполнять `PRODUCTION_DATABASE_URL` чужим URL или staging credentials, менять пароли, запускать миграции до установления истинного источника production URL.
- Сначала установить реальную production DB у провайдера, занести секрет только в GitHub Environment `production` (не в код/чат), убедиться, что production/staging физически разные.

**Блокер B — drift схемы production относительно main.**
- `Staging Smoke` фиксирует `production schema drifted from main; expected=0059_worker_manager_future_integrity.sql active=0066_tender_bid_rounds.sql`: https://github.com/avdeevgreyfog-cmd/outsourcing-operations-os/actions/runs/37741346723 .
- Нужно разобраться, как более новая схема попала на production раньше кода, сохранить данные, устранить drift согласованной процедурой; **не откатывать базу вслепую**.

**Блокер C — порядок release lineage.**
- После прямого добавления статического HTML в main: `Production Release Lineage` не прошёл — commit main `2d9e7ac8...` отсутствует в `beta`: https://github.com/avdeevgreyfog-cmd/outsourcing-operations-os/actions/runs/37766528316 .
- Нужно восстановить корректную последовательность promotion `beta → main`; учитывая разошедшиеся ветки, не делать силовой push/reset без согласованного плана.

**Блокер D — Vercel connector.**
- На момент проверки чтение/deploy текущего Vercel проекта через подключённый инструмент возвращали `403 forbidden`/иногда `404 project not found`. Нового серверного Vercel deployment не производили.
- Проверить права GitHub integration/Vercel в подходящем scope и состояние автоматического staging preview. Наличие GitHub CI success не означает наличие обновлённой страницы на production.
